This page shows the minimum setup for calling the REST API and subscribing to WebSocket streams.

## 1) Prepare credentials

| Value | Description |
|---|---|
| `REST_URL` | `https://api-gw.verolabs.co/api/v1` |
| `AUTH_URL` | `https://api-gw.verolabs.co/api/authen` |
| `JWT` | Bearer token returned by the Ory login/session flow |
| `SESSION_TOKEN` | Ory session token used by selected native flow endpoints |
| `WS_URL` | `wss://streaming.verolabs.co/connection/websocket` |

<Info>
Do not commit bearer tokens, session tokens or account identifiers to source control.
</Info>

## 2) Call a public REST endpoint

```bash
curl --request GET \
  --url "https://api-gw.verolabs.co/api/v1/health"
```

## 3) Call an authenticated REST endpoint

```bash
export REST_URL="https://api-gw.verolabs.co/api/v1"
export JWT="<jwt>"

curl --request GET \
  --url "$REST_URL/users/accounts" \
  --header "Authorization: Bearer $JWT"
```

## 4) Subscribe to a streaming channel

Use the Centrifugo WebSocket endpoint and subscribe to the channel pattern you need:

```text
wss://streaming.verolabs.co/connection/websocket
mkt:depth:VN30F1M-G1
order:{accountId}
```

## Key rules

| Rule | Note |
|---|---|
| Keep credentials private | Never expose bearer or session tokens in client-side logs or support messages |
| Log request IDs | Helps support trace failed requests |
| Use documented filters | Match path and query parameters exactly as shown in the reference |
| Retry carefully | Use backoff for temporary failures |
